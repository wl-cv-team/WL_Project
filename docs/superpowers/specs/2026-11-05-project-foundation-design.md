# WL_Project 기초 설계

작성일: 2026-11-05 · 상태: 초안 (팀 리뷰 전)

## 1. 의도와 이유

인상(snatch) 영상에서 **측정 가능한 것을 신뢰할 수 있게 측정하고, 그 데이터를 쌓아 나중에 분석하는 연구 기반**을 만든다.

이 저장소는 아카이브 저장소(`wl-cv-team/WL_Project_archive`)를 이관한 것이 아니라 **기초부터 다시 세운 것**이다. 아카이브는 노트북이 개발의 중심이었다. 로직의 상당 부분이 노트북 셀에 있었고, 테스트가 노트북을 통째로 실행해서 검증했다. 그 구조는 협업자가 접근하기 어려웠다. 새 구조의 목적은 여러 사람이 단계별로 나눠 개발하고 PR로 리뷰할 수 있게 하는 것이다.

## 2. 목표

- **G1. 객체 탐지 품질** — 바벨 원판을 정확히 탐지하고, 주변 물체는 탐지하지 않는다. (초반 전략의 핵심, 아래 3절)
- **G2. 바 경로 추적** — 바가 지면에서 수직으로 움직이는지 추적해 판별할 수 있게 한다. 판별 지표(예: 좌우 분산)는 문헌과 데이터를 보고 빌더가 제안한다.
- **G3. 구간 분할과 구간별 측정** — 시작자세 → First Pull → Second Pull → Catch → Recovery를 구분한다. 구간별 속도와 신체 부위(무릎, 골반, 발목 등)의 속도 비율을 병렬로 얻는다.
- **G4. 전문가 라벨 수집** — 팀 내 도메인 전문가와 외부 코치가 "좋은 sign / 나쁜 sign" 수준으로 구분해 준 라벨을 받는다. 정답 라벨이 아니라 참고 라벨이다.
- **G5. 연구 질문** — First Pull 시간이 Second Pull에 미치는 영향을 조사하고, 가능하면 최종 득점 중량과의 연관성까지 추적한다. (1차 문헌 검색에서는 이를 직접 검증한 연구를 찾지 못했다. 얕은 검색이므로 추가 확인이 필요하다.)
- **G6. 문헌 목록** — 이 동작들의 역학관계를 논문으로 다룬 사례를 목록으로 정리한다. 위치는 `docs/literature/`.
- **G7. 쓰임새 탐색** — 단순 영상만으로 만든 모델이 어디에 유용한지 찾는다. 마커 기반 모션캡처(Helen Hayes 방식 등)와의 성능 비교는 목표가 아니다. 팀에 그 데이터도 없다.

## 3. 초반 전략: 탐지 품질 우선, TCN 시도

- **객체 탐지 기능을 먼저 구현하고, 탐지 품질을 높이는 것이 초반 전략의 핵심이다.** 이후 단계(G2~G5)의 신뢰도가 모두 탐지 품질에 걸려 있다.
- **TCN(Temporal Convolutional Network) 모델을 사용해 보는 것을 팀이 선호한다.** 팀원과 논의한 결과이며, 이번 접근에서 시도할 방향이다.
- TCN을 어느 단계에 적용할지는 이 문서가 정하지 않는다. (제 추측: 프레임 시퀀스를 다루는 구간 분할이나 탐지 결과의 시간축 보정 후보. 확정 아님.) 빌더가 근거를 제시해 팀과 정한다. 탐지 모델과 TCN을 어떻게 연결할지도 같은 방식으로 정한다.
- 모델 종류는 코드에 고정하지 않고 설정으로 교체할 수 있게 한다.

## 4. 비목표와 반목표

**비목표 (지금 하지 않는다)**
- 좋은 동작과 나쁜 동작의 판정. 1~4단계에서 데이터가 쌓이고 객관성이 갖춰진 뒤에 시작한다. 서두르지 않는다.
- 종합 점수나 기술 등급 산출.
- 인상 외 종목(파워스내치 포함).
- 마커 기반 모션캡처와의 비교 평가.

**반목표 (기술적으로 동작해도 실패로 본다)**
- 근거가 쌓이기 전에 동작의 좋고 나쁨을 단정하는 문장을 결과나 문서, 코드 메시지에 쓰는 것.
- 비유적 표현으로 결과를 설명하는 것. 결과는 쌓은 뒤에 분석해서 제시한다.
- 측정하지 못한 값을 채워서 성공처럼 보이게 하는 것.
- 노트북에서 개발이 진행되는 것.

## 5. 제약

- 기본 실행 환경: MacBook M2 Air 8GB. 작은 모델, 작은 입력으로 먼저 검증한다.
- 데이터: 54개 영상, 선수 / 아마추어 선수 / 초심자가 섞여 있고 **같은 사람이 여러 영상에 등장**한다. 일반화를 증명했다고 주장하지 않는다.
- 영상에 사람이 찍혀 있으므로 `data/`는 git에서 제외한다. 외부 공유는 사전 승인을 받는다.
- 협업: 단계별로 나누고, `main` 직접 push 없이 `feature/<주제>` 브랜치와 PR 상호 리뷰로 진행한다.

## 6. 결정 사항 (사용자가 정한 것)

- 주된 코드는 패키지 안의 `.py` 소스다.
- 노트북에는 TDD 코드와 로직을 두지 않는다. 간단한 조건문만 허용한다.
- 노트북과 `.py` 튜토리얼의 역할은 세 가지다. 사용자와 동료를 위한 난이도를 낮춘 설명, 실험, 간편한 보조 실행. 모두 `src/`를 불러다 쓰는 쪽이다.
- 사람 단위로 학습/검증을 분할한다. 같은 사람을 양쪽에 넣지 않는다.
- 이중 무릎굽힘(double knee bend)은 최상위권 선수에게 나타나는 동작이라 일반인과 별도 취급이 필요할 수 있다. **결론을 내지 않고 열린 질문으로 남긴다.**
- 라벨은 참고 라벨(좋은/나쁜 sign)까지만 받는다.

## 8. 데이터 원칙

- `data/metadata/videos.csv`를 영상 선택과 split 생성의 기준 manifest로 쓴다. (아카이브에서 이어받음) 그룹, 사람 ID, 수준, 반복 정보는 폴더 이동이 아니라 manifest 열로 관리한다.
- 원본 영상은 수정하지 않는다. 파생 데이터는 별도로 저장한다.
- 측정이 불가능하면 값을 채우지 않고 `N/A`와 사유를 남긴다.
- 기존 데이터는 `~/Downloads/drive-download-20261104T143056Z-1-001.zip`(132MB, 470개 파일)에 있다. 구성은 `raw/` 영상 54개, `metadata`, `annotations`, `splits`, `plate_dataset`(30장), `plate_dataset_v2`(train 110 / validation 40)다. 구조 합의 후 `data/`로 복사한다.

## 9. 기술 기본값 (제 선택, 확정 아님)

uv, Python 3.12, 아카이브에서 쓰던 라이브러리(OpenCV, PyTorch, NumPy, Ultralytics, pandas, matplotlib, torchvision)로 시작한다. M2 Air에서 이미 동작하던 구성이다. TCN 구현에 추가 라이브러리가 필요하면 도입 이유와 대안을 설명하고 팀의 승인을 받는다.

## 9-1. 첫 계획의 범위 (사용자 확정)

**포함:** 저장소 뼈대(7절 구조, `pyproject.toml`, `.gitignore`, README, PR 템플릿), 데이터 이동과 사람 단위 split 재생성, `docs/contracts/` 단계 간 약속 문서(탐지 출력 형식 포함), 탐지 단계(평가 방법과 기준선 정의, 아카이브 라벨 점검, 오탐 별도 측정, 품질 향상 실험).

**제외:** 바 경로 수직성 판별, 구간 분할, 구간별 속도 측정, TCN 구현, 포즈 추정. `docs/roadmap.md`에 순서와 의존성만 적는다.

**라벨 점검 후 정하는 것:** 아카이브 라벨(`plate_dataset` 30장, `plate_dataset_v2` 150장)을 재사용할 수 있는지, 재라벨링이 필요하다면 담당자와 규모. TCN의 적용 위치, "시도했으나 효과 없음" 결과의 허용 여부, 적용 위치 승인 절차. 두 가지 모두 **라벨 점검 결과를 보고 팀이 정한다.** 점검 전에는 어느 쪽도 가정하지 않는다.

**제 선택 (확정 아님, 리뷰 시 확인):**
- 포즈 추정은 3단계에서 다룬다. 후보는 Ultralytics YOLO26-pose(검색 결과상 현재 최신)와 YOLO11-pose(안정된 대안)다. 아카이브의 YOLOv8(2023년)은 쓰지 않는다. 모델은 설정으로 교체 가능하게 하고, 선택은 그 단계에서 M2 8GB 실측으로 정한다. 같은 이유로 **탐지(1단계)의 기반 모델도 기준선 단계에서 최신 세대를 비교해 정한다.** 버전 정보는 공식 문서에서 다시 확인한다.
- 아카이브는 참고용이다. 코드는 가져오지 않고 데이터와 manifest만 사용한다.
- CI와 노트북 검사(노트북에 로직이 없는지)는 첫 PR 이후 작게 시작한다.
- 표현 규칙은 문서뿐 아니라 출력 라벨과 지표 이름에도 적용하고, PR 체크리스트로 확인한다.
- `videos.csv`는 `person_id`, `group`, `split_role` 열을 이미 가지고 있다. split 재생성에 이 열을 사용한다.

## 9-2. 탐지 첫 실험 순서 (사용자 확정)

1. **YOLO26으로 먼저 기준선을 만든다.**
2. 그 뒤 YOLO11과 YOLOv8(비교용)을 같은 데이터, 같은 split, 같은 평가 조건으로 돌려 비교한다.
3. 비교는 한 번에 한 축(모델 세대)만 바꾸고, seed와 조건을 기록한다.

## 10. 빌더에게 맡기는 것

- 패키지 이름과 모듈 내부 구성.
- 단계 간 입출력 형식의 세부 설계 (`docs/contracts/`에 문서화).
- 바 경로 수직성 판별 지표 제안.
- TCN 적용 위치 제안과 근거.
- 탐지 품질의 평가 지표와 기준선 설정.
- 테스트 구성. 단, 노트북은 실행하지 않는다.
- 문헌 정리의 깊이와 형식.

- TCN 적용 위치와 승인 절차. (9-1절: 라벨 점검 후 결정)
