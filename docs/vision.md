# 비전

출처: `docs/superpowers/specs/2026-11-05-project-foundation-design.md`의 1, 2, 4절.

## 의도와 이유

인상(snatch) 영상에서 **측정 가능한 것을 신뢰할 수 있게 측정하고, 그 데이터를 쌓아 나중에 분석하는 연구 기반**을 만든다.

이 저장소는 아카이브 저장소(`wl-cv-team/WL_Project_archive`)를 이관한 것이 아니라 기초부터 다시 세운 것이다. 아카이브는 노트북이 개발의 중심이었다. 로직의 상당 부분이 노트북 셀에 있었고, 테스트가 노트북을 통째로 실행해서 검증했다. 그 구조는 협업자가 접근하기 어려웠다. 새 구조의 목적은 여러 사람이 단계별로 나눠 개발하고 PR로 리뷰할 수 있게 하는 것이다.

## 목표

- **G1. 객체 탐지 품질** — 바벨 원판을 정확히 탐지하고, 주변 물체는 탐지하지 않는다.
- **G2. 바 경로 추적** — 바가 지면에서 수직으로 움직이는지 추적해 판별할 수 있게 한다. 판별 지표는 문헌과 데이터를 보고 빌더가 제안한다.
- **G3. 구간 분할과 구간별 측정** — 시작자세, First Pull, Second Pull, Catch, Recovery를 구분한다. 구간별 속도와 신체 부위(무릎, 골반, 발목 등)의 속도 비율을 병렬로 얻는다.
- **G4. 전문가 라벨 수집** — 팀 내 도메인 전문가와 외부 코치가 두 범주로 구분해 준 참고 라벨을 받는다. 정답 라벨이 아니다.
- **G5. 연구 질문** — First Pull 시간이 Second Pull에 미치는 영향을 조사하고, 가능하면 최종 득점 중량과의 연관성까지 추적한다. 1차 문헌 검색에서는 이를 직접 검증한 연구를 찾지 못했다. 얕은 검색이므로 추가 확인이 필요하다.
- **G6. 문헌 목록** — 이 동작들의 역학관계를 논문으로 다룬 사례를 목록으로 정리한다. 위치는 `docs/literature/`.
- **G7. 쓰임새 탐색** — 단순 영상만으로 만든 모델이 어디에 유용한지 찾는다. 마커 기반 모션캡처와의 성능 비교는 목표가 아니다.

## 비목표와 반목표

**비목표 (지금 하지 않는다)**
- 동작의 판정. 데이터가 쌓이고 객관성이 갖춰진 뒤에 시작한다. 서두르지 않는다.
- 종합 점수나 기술 등급 산출.
- 인상 외 종목(파워스내치 포함).
- 마커 기반 모션캡처와의 비교 평가.

**반목표 (기술적으로 동작해도 실패로 본다)**
- 근거가 쌓이기 전에 동작을 단정하는 문장을 결과, 문서, 코드 메시지에 쓰는 것.
- 비유적 표현으로 결과를 설명하는 것. 결과는 쌓은 뒤에 분석해서 제시한다.
- 측정하지 못한 값을 채워서 성공처럼 보이게 하는 것.
- 노트북에서 개발이 진행되는 것.

## 표현 규칙

문서, 코드, 커밋 메시지, 출력 라벨, 지표 이름에 모두 적용한다. PR 체크리스트로 확인한다.

1. **근거 전에 판정 금지.** 데이터가 쌓이고 객관성이 갖춰지기 전에는 동작의 우열을 말하지 않는다.
2. **비유 금지.** 결과는 비유가 아니라 측정한 대상과 값으로 설명한다.
3. **측정값과 `N/A`+사유 중심.** 결과는 측정값으로 쓴다. 측정하지 못했으면 값을 채우지 않고 `N/A`와 사유를 남긴다.
